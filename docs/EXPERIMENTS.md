# 实验、选型与关键取舍

工作主线：场景需求 → 检测/Tracker 选型 → 指定身份恢复 → 检测微调 → 固定对照与消融 → PC 应用和复现验证。只保留能回答具体问题的实验；旧 GT ID、旧事件口径的过程性结果不作为公开证据。

## 检测器选型：11n／26n → 26s

初期在 MOT17-02/04/05 开发侧比较 11n、26n，640/960，及 26n 的 O2M/O2O。固定阈值下 11n O2M/960 有更多 TP，也有更多 FP；26n O2M/960 是工程工作候选，并非所有质量指标的赢家。960 下 11n TP/FP 为 42,368/19,316，26n O2M 为 40,210/15,520，26n O2O 为 37,970/12,196。O2M 较 O2O 保留更多候选行人，但也带来更多误检。

后续单独比较 26n 与 26s，沿用 O2M/960 和跟踪评价。开发 AP50 从 59.70% 到 61.51%，召回率从 55.04% 到 57.51%；T2 HOTA 从 40.08 到 42.90，IDF1 从 47.83 到 51.32，IDSW 也从 237 增至 272。因此升级依据是检测和下游整体质量收益，同时保留身份切换方面的代价。

原始阶段表：[初期检测选型](../results/detector_initial.csv)、[26n→26s 检测对照](../results/detector_upgrade.csv)。这些是全行人检测口径，独立于旧的指定 GT ID/恢复事件清单，不将旧指定目标结果混入。

## Tracker、GMC 和原生 ReID

以相同 26s O2M/960 检测为输入：验证集 T0 ByteTrack HOTA/IDF1 为 39.03/46.90，T1 BoT-SORT 为 40.00/48.18，T2 加 GMC 为 44.75/54.95，T3 再加内置 ReID 为 44.07/53.90。对应 Tracker update 平均耗时约 1.09/1.10/11.90/54.86 ms。

选用 T2 作为基础，原生 ReID 默认关闭，在外部 ShortLink/A2 中显式控制外观使用。耗时仅覆盖 Tracker update，不是完整视频 FPS。移动机位 05 的 TrackTrack 局部表现可以优于 T2，不能宣称 T2 在所有移动场景最优。T4/T5 使用普通后 NMS 输入，不等同于完整 TrackTrack 的宽松原始检测协议。

原始阶段表：[Tracker 选型](../results/tracker_selection.csv)。

## CrowdHuman 微调与下游传递

15,000 张训练图、4,370 张验证图；主训练 100 轮，960、batch 8、nbs 64、AdamW、初始学习率 0.0005、余弦衰减、bf16。保留 person 分类输出对应的预训练参数及隐藏通道，重新加载核对；ignore 区域对 O2M/O2O 两分支未匹配负分类项做 IoA≥0.5 屏蔽，正样本优先。以全精度 CrowdHuman MR^-2 选择 checkpoint，平局参考 AP。

检测验证 AP50 从 70.89% 到 81.37%，召回率从 70.92% 到 81.31%。检测改进不保证身份指标全部改善：T2 验证 HOTA 从 45.754 到 53.677、IDF1 从 57.181 到 67.755，但 IDSW 从 145 到 166、Frag 从 392 到 496。

必须分开两组对照：

- 相同 ShortLink 和相同 A2 参数，只换检测权重，见[固定参数对照](../results/detector_fixed_control.csv)。例如使用微调正式 A2 参数时，验证覆盖率 40.02%→55.89%，W 8→25，稳定恢复 11/14→14/14；收益伴随误跟代价。
- 微调前原参数系统与微调后重新选参系统的四行系统比较，见[开发/验证系统表](../results/devval_system.csv)及[测试系统表](../results/test_system.csv)。开发/验证表的 `target_preset` 明确区分 Original、Tuned 和 ID-lock；其中微调完整系统采用最后选定参数，而非微调后沿用原参数的中间结果。这是最终配置对比，不能全归因于检测权重。

ShortLink 108 组和 A2 2,916 组按开发集选择，验证只检查。验证集经过重复使用，所以作为验证/诊断证据；测试序列不用于本次调参。[A2 选择记录](../results/a2_selection.json)和[ShortLink 选择记录](../results/shortlink_selection.json)保留选择依据；本次整理未重跑全量网格。

## A0／A1／A2：共享最终 Tracker 的策略比较

A0 锁定初始 Tracker ID；A1 在绑定 ID 不可见时，立即选与初始锚点最相似的观察轨迹，没有门槛、确认或模板更新；A2 为完整保守恢复策略。A1 是朴素基线，不代表先进 ReID 方法。三者共享相同微调检测、BoT-SORT＋ShortLink 输出和初始化协议，A1/A2 使用相同 RGB448 描述符。

## 采用部件的消融：A、C、D

- **A，恢复策略**：上面的共享 Tracker A0/A1/A2 对照，解释“直接追 ID”和“直接按外观重绑定”的局限。
- **C，多模板库**：开发 C 18,087→18,210、稳定恢复 22/32→23/32；验证无差异；测试 C 4,612→4,688，覆盖率 89.50%→90.98%，恢复 16/18→17/18，W 都为 30。
- **D，EMA**：开发 C 17,984→18,210，恢复数量不变；验证无差异；测试 C 4,611→4,688、恢复 16/18→17/18，W 都为 30。

相同 Tracker 共享缓存的[本次复现表](../results/policy_reproduction.csv)直接支持这些比较。其他后处理消融见[当前口径部件表](../results/postprocessing_ablation.csv)。最新开发/验证身份交接没有相关触发，不能以该组零差异证明身份交接收益；机制正确性由同帧/代际测试以及迁移逐帧等价检查支撑。关闭 A2 motion 开关影响多条运动分支，不能解释为单一运动半径消融。

## 未采用尝试与取舍：F、G、H、I

| 主题 | 问题 → 尝试 | 分析与最终决定 | 保留形式 |
| --- | --- | --- | --- |
| F：强证据保留、弱证据联合确认 | 遮挡后外观短暂变弱 → 保留此前强证据并暂停计时，尝试低分外观与几何联合确认 | 需要防止弱证据累计成错误身份，默认关闭，未作为最终收益来源 | `research/temporal_evidence.py`，独立依赖正式 A2 |
| G：加权累计、恢复后持续复核 | 逐帧阈值可能打断恢复 → 按质量累计，并持续检查已恢复身份 | 容易增加错误恢复或误阻断，需要权衡，默认关闭 | `research/accumulated_review.py`，内含所需扩展，无 v8 文件依赖 |
| H：恢复后多证据复核 | 仅按外观复核可能误拒绝 → 联合外观、运动与 ID 连续性 | 降低误拒绝也可能放行错误身份，未替换正式方案 | `research/joint_review.py`，无 v8/v9 文件依赖 |
